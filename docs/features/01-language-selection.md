## 1. Проблема

Бот повністю переведено з російської на українську (див. `docs/03-BOT-UX.md`), але мова інтерфейсу зараз одна — жорстко зашита в тексти й не залежить від користувача. Частина потенційної аудиторії (діаспора, англомовні користувачі) не володіє українською настільки, щоб зручно користуватись ботом. Наразі це поза увагою — фіча лише резервує місце в реєстрі, щоб рішення не загубилося.

## 2. Область

**Входить (коли дійде черга):**
- [ ] Поле `User.language` (`uk` за замовчуванням для нових і вже існуючих користувачів — без цього старі акаунти зламаються після міграції)
- [ ] Вибір мови під час онбордингу (крок після часового поясу, до підключення календаря) або окремий пункт у `/settings`
- [ ] Модуль текстів бота (`uk.ts`/`en.ts` або еквівалент) — усі повідомлення й підписи кнопок з `docs/03-BOT-UX.md`, продубльовані на англійську
- [ ] `parseDuration`/`parseTime`/`parseManualDate` — розпізнавання формату відповідно до мови (укр `год`/`хв`, англ `h`/`m`)

**Не входить (осознанно відкладено):**
- Автовизначення мови з `ctx.from.language_code` Telegram — *почати з явного вибору користувачем, автовизначення додати окремо, якщо буде запит*
- Мови, відмінні від укр/англ — *не заявлено потреби, розширювати реєстр мов, коли з'явиться конкретний користувач*
- Переклад технічної документації (`01-PRD.md`, `02-TECH-SPEC.md`) — *це внутрішні документи проєкту, не інтерфейс бота*
- Реалізація в цій сесії — *ця фіча зараз лише зареєстрована, код не пишеться*

- [ ] Жодного інлайнового рядка user-facing тексту поза текстовим модулем
- [ ] `parseDuration`/`parseTime`/`parseManualDate` розпізнають формат відповідної мови
- [ ] Тексти обох мов звірені з відповідними UX-документами
- [ ] `npm run typecheck && npm test` — зелені

## 8. Ризики

| Ризик | Ймовірність | Що робимо |
|---|---|---|
| Дублювання рядків між файлами (як зараз) ускладнить підтримку двох мов одночасно | висока, якщо не ввести текстовий модуль зараз | Проєктувати текстовий модуль як обов'язкову передумову, не опціональне поліпшення |
| Зміна формату вводу дати/часу/тривалості за мовою заплутає користувачів, які звикли до одного формату | середня | Приймати обидва формати незалежно від обраної мови, підказки показувати мовою UI |
